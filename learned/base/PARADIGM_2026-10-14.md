# Changing the substrate or the paradigm (proposal, 2026-10-14; no runs)

Premise accepted: cheapness and honesty only matter past a usability floor (coherent English in, coherent and
relevant English out, over a short dialogue). Nothing in the record is near that floor: the engine's samples are
"locally grammatical phrases, no sustained meaning" (R25-cx).

## The diagnosis to act on
The substrate problem is not counts versus networks. It is **exposure**. Every trained part of this project saw
21M tokens of Gutenberg. No architecture reaches usable English from 21M tokens; the quantity that crosses the floor
is on the order of 1-2 billion tokens for a model of 30-100M parameters (the Chinchilla ratio, 20 tokens per
parameter). Counts cannot use more data profitably (R25-cv, cw: 0.09 alone, 0.00 in the mix); a network can.
So the paradigm change is: **stop tuning the combiner; buy exposure**, and keep the engine's modules as the things a
plain network lacks.

## Four ways to alter the substrate, cheapest proof first

### A. Synthetic controlled-vocabulary corpus, tiny network (the TinyStories recipe)
Eldan and Li (2023) trained 2.5M-33M parameter models on ~500M tokens of GPT-generated children's stories with a
3-4 year old's vocabulary; the 33M model writes coherent, grammatical, causally consistent multi-paragraph stories
and answers questions about them. One GPU, hours. That is exactly this project's usability floor, and this project
already has a generator (the "generator stories / controlled set", R24) and a story-question battery.
- Substrate: a 30-60M parameter transformer or RWKV-7 trained from scratch on 0.5-1B tokens of synthetic stories
  and dialogues with a vocabulary of ~3,000 words, plus a slice of real Gutenberg so held-out real text is scored.
- Data: generated by an API model from a vocabulary list and story/dialogue templates (the project's own generator
  can produce structure; the API model produces the prose). Facts deliberately excluded: no dates, no named real
  entities. This is "LLM minus facts" made literal at the data level.
- Compute: Colab T4, ~10-30 h for 1B tokens at 30-60M params (the owner's rule: hours go to Colab). Laptop CPU
  does inference at 100+ tokens/s.
- Proof of usability: TinyStories-style grading (grammar / consistency / plot, 0-10) on held-out prompts by an API
  judge, plus the existing question panels under +1 / -3.
- Why this is the paradigm change: the model learns grammar, discourse and simple reasoning from a corpus whose
  every sentence is cheap and controlled; the world's facts never enter the weights.

### B. Pretrained small open model as the fluency organ, this engine around it (the subtractive fast path)
Take a 135M-360M open model (SmolLM2-class, trained on ~2T tokens, Apache licensed) and treat it as the fluency
substrate. Wrap it with the parts this project already built and that a stock model lacks:
- dynamic evaluation on the text being read (R26 T01; largest single gain in the record),
- copy / keyed memory and a kNN-LM datastore for facts (Khandelwal et al. 2020: retrieval from a datastore cuts
  perplexity without retraining; RETRO 2022: a retrieval model matches one 25x larger),
- abstention under +1 / -3 (the one asset of the E1-E8 arcs),
- the role reader as a fact-checker on the model's answers (verifier, fail-closed).
Fast: usable dialogue within days. Honest cost: the substrate is not ours. Its value is as a **control**: it
measures what the engine's modules add on top of a competent substrate. If they add nothing, the modules are the
wrong investment regardless of substrate; if they add honesty and retrieval the stock model lacks, that is the
product, and path A then replaces the substrate with one trained here.

### C. Neural proposer, symbolic verifier (the old engine returns as a judge, not a speaker)
Keep whichever substrate A or B gives, and put the rejection-first machinery back where it was good: checking.
The model proposes an answer or a statement; the verifier (role reader, world state, retrieval, the +1 / -3 rule)
rejects or abstains. This is the only arrangement in the record that ever beat the model on precision, and the
pattern in which "LLM minus facts, facts by search, keep the logic map" is coherent: the network holds the logic
map, search holds the facts, the verifier holds the honesty.

### D. Distillation of reasoning traces (later; needs A or B first)
Once a substrate speaks, train it on API-generated (question, search result, reasoning, answer) traces so that it
learns to call retrieval and to abstain, Toolformer-style, rather than to recall. This is how "keep the logic,
drop the facts" is taught; it cannot be taught to a model that cannot yet read.

## What is kept from the current engine
Dynamic evaluation, copy memory, the learned groups and vectors (as a cheap retrieval index), the role reader (as
a verifier), the question panels and the +1 / -3 rule, the prereg discipline. Dropped: the Kneser-Ney and
self-searched counters as prediction components (they are what the extra 1B tokens replaces), the mixing contexts,
the hand state rules.

## What the floor would be measured by (fixed before any run)
1. A held-out set of 200 story / dialogue prompts graded 0-10 for grammar, coherence and relevance by an API judge,
   blind, ours against SmolLM2-135M and against the current engine; floor = within 1 point of the 135M model.
2. The 1,800 untouched question panels under +1 / -3, model with abstention threshold versus ours.
3. Real held-out Gutenberg bits/word, so the synthetic corpus is shown not to have broken real-text reading.
4. CPU-seconds per 100 generated tokens on the laptop.

## Recommended order
B first (one week: it is the control and it gives a usable system to test the modules on), A in parallel on Colab
(it is the long pole and it does not wait on anything), C as soon as either speaks, D after.

## What this costs in belief
"Pure stdlib, no probability, hand rules" was given up on 2026-10-08. What remains to give up is "the substrate is
trained from 21M tokens of Gutenberg on a laptop." The project cannot cross the usability floor on that exposure;
every result since R24 is consistent with this.
